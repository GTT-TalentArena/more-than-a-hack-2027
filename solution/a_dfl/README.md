# Candidate A with a ball-free model trained on other games (#47)

Candidate A v1.6 (`solution/a_opus`, unchanged) with one part replaced: its **ball-free team model**, the logistic
regression on team shape that says which side has the ball where the ball cannot be seen. A trains it on the match
it labels, with ball proximity as the targets. Here it is trained once on the **DFL development matches**, with the
DFL possession labels, and applied unchanged: nothing is fitted on the match being labelled.

Why, the hypotheses, the training data, the weight rule and the evaluation plan, all written before any run:
[`docs/experimentos/A_DFL_BALLFREE.md`](../../docs/experimentos/A_DFL_BALLFREE.md).

## Results on the development matches

Leave-one-match-out on the five DFL development matches, degraded profiles × seeds (details, tables and the
post-hoc analysis in the plan document, sections 7–9):

- **Gate passed.** Mean spellF1 0.4382 against A's 0.4247, above A on 3 of 5 matches, macroF1 +0.008. The ball-free
  model agrees with the DFL labels more often than A's on the frames where it is used (no ball: 84.6% → 86.2%).
- **But the gain comes from A's own model missing in a half** (too few proximity-confident frames on DFL). Where A
  has its model in both halves, which is BAR–ATH's case, the variant **ties** with A (−0.0016 over 39 runs).
- **Against A with the ball-free model off**, what A becomes if self-training on the provided match is ruled out,
  the variant is higher on all five matches (+0.040 to +0.084).

The reserved comparison (`J03WN1`, `J03WR9`) is Edu's and has not been run.

## Running

Exactly as candidate A, with the module name changed (same requirements: `solution/a_opus/requirements.txt`):

```bash
python -m solution.a_dfl --out evaluation/results/a_dfl.csv
python evaluation/validate_submission.py evaluation/results/a_dfl.csv
```

Through P0 and the team's Docker image, with `configs/candidate_a_dfl.json`:

```bash
docker compose run --rm modelo modelo --config configs/candidate_a_dfl.json --repetir
```

Every flag of candidate A works (`--log`, `--set`, `--evidence`). The log is A's, plus one first line on stdout with
the model's provenance. A's line `ball-free team model: held-out agreement … -> weight …` keeps its format: the
agreement is now the fixed model's agreement with ball proximity on this match, printed and not used, and the weight
is the fixed one.

## How it differs from A

- **One function.** A's pipeline calls `ballfree.cross_fit` to fit its ball-free model and
  `ballfree.weight_from_accuracy` to weigh it. `model.installed()` replaces both for the length of the run: the first
  returns the logits of the fixed model, the second its fixed weight. Every other number is A's: evidence, decoder,
  constants, self-calibration, and the frames where the ball-free evidence counts (full weight without a ball, half
  where the ball is in sight but nobody clearly controls it).
- **Antisymmetric model.** Exchanging home and away negates the logit, so the model cannot prefer the home side of the
  matches it was trained on. It uses the 30 columns of A's features that change sign under that swap, and no
  intercept (`model.py` explains which and why; `tests.py` checks it against A's feature code).
- **Guard.** `weights.py` records the SHA-256 of A's feature code. If any of those files changes, the variant refuses
  to run until it is retrained: the coefficients would no longer describe what the pipeline computes.

## Training and development

Needs the DFL open data of the five development matches, through Edu's harness (`heldout/`):

```bash
python -m heldout fetch J03WMX J03WOH J03WOY J03WPY J03WQQ
python -m heldout convert J03WMX J03WOH J03WOY J03WPY J03WQQ
python -m solution.a_dfl.train      # writes solution/a_dfl/weights.py and salidas/a_dfl/folds/
python -m solution.a_dfl.develop    # leave-one-match-out: A, A without ball-free, variant
python -m solution.a_dfl.develop --summary
```

Both refuse the reserved matches (`J03WN1`, `J03WR9`). The final comparison on those runs through the harness
unchanged, with `--model v=configs/candidate_a_dfl.json` (`heldout/README.md`).

Tests, synthetic only: `python -m solution.a_dfl.tests --full`.
